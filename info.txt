СПРАВОЧНИК — данные для будущего Windows-приложения
====================================================

Назначение этой папки
---------------------
Изолированный снимок данных корпоративного справочника из Telegram-бота
Guide-Rest (restbot). Позже эти данные планируется вынести в отдельное
приложение под Windows.

Оригиналы файлов пока остаются в корне проекта restbot — бот продолжает
их читать оттуда. Здесь лежит копия для независимого развития.


Что это за данные
-----------------
Справочник — база готовых ответов сотрудников по отделам: вопрос/тема,
текст ответа, опционально фото и документы. Использовался в Telegram
для быстрого поиска инструкций и шаблонов ответов клиентам.

Отделы (как в config.py бота):

  Файл                    Отдел              Ключ JSON
  --------------------    -----------------  ----------
  guide.json              Тех. Поддержка     questions
  guide_lawyers.json      Юристы             questions
  guide_spp.json          СПП                questions
  guide_managers.json     Менеджеры          questions
  templates.json          Шаблоны ответов    templates
                          (только Тех. Поддержка)


Структура записи (questions / templates)
----------------------------------------
Обязательные поля:
  id         — целочисленный идентификатор
  question   — заголовок пункта / тема
  answer     — текст ответа (может быть длинным, с переносами)

Опциональные поля медиа:
  photo      — устаревшее: один Telegram file_id фото
  photos     — список Telegram file_id фотографий
  documents  — список объектов {file_id, file_name} для документов

Иерархия (папки / подпункты, до 2 уровней):
  parent_id     — id родительского пункта; null/отсутствие = корень
  has_children  — true, если пункт является «папкой» с дочерними

Пример корневого пункта:
  {
    "id": 2,
    "question": "Как получить закрывающие документы?",
    "answer": "...",
    "photo": "AgACAgIAAxkB..."
  }

Пример папки с дочерними пунктами:
  родитель: { "id": 10, "has_children": true, "parent_id": null, ... }
  дочерний: { "id": 11, "parent_id": 10, ... }


Как использовались в боте
-------------------------
Точка входа: bot_new.py
Загрузка/сохранение: utils/data_manager.py
  — load_guide(file_name) / save_guide(...)
  — load_templates(file_name) / save_templates(...)
  — файлы читались из корня репозитория (относительный путь)

Просмотр и поиск: handlers/guide_handlers.py
  — постраничный список пунктов
  — открытие папок (подпункты по parent_id)
  — показ ответа + медиа (photos / documents через Telegram file_id)
  — поиск внутри отдела и глобальный поиск по всем отделам
  — морфологический поиск (pymorphy3) в utils/smart_hybrid_search.py

Редактирование: handlers/edit_handlers.py
  — добавление / правка / удаление пунктов и шаблонов
  — создание папок и подпунктов
  — накопление длинных ответов из нескольких сообщений

Права доступа (роли):
  user      — только просмотр
  executor / manager / admin — просмотр + редактирование
  admin     — админ-панель и управление ролями

Меню по отделам задаётся в config.py (DEPARTMENTS, клавиатуры).


Важные ограничения для Windows-приложения
-----------------------------------------
1. Медиа (photos, photo, documents) хранят Telegram file_id, а не
   локальные файлы. В десктоп-приложении эти ID сами по себе не
   откроются — нужна миграция: скачать файлы через Bot API заранее
   или хранить локальные пути/байты.

2. Кодировка файлов: UTF-8.

3. Формат — обычный JSON с отступами (indent=2), ensure_ascii=False.

4. templates.json относится только к отделу «Тех. Поддержка»; у
   остальных отделов шаблонов не было.
