# REST INFO

Windows-приложение — корпоративный справочник ответов по отделам (техподдержка, юристы, менеджеры, СПП, шаблоны) с ролями пользователей и синхронизацией через Яндекс.Диск.

Репозиторий: https://github.com/Konstantinino/spravochnik (код и история версий; **данные и установщики** — на Яндекс.Диске).

## Установка на ПК

1. Скачайте `REST-INFO-Setup-*.exe` с Яндекс.Диска из папки **`REST INFO/updates/`**  
   (после локальной сборки файл также лежит в `app/release/`)
2. Установите как обычную программу
3. На рабочем столе появится ярлык **REST INFO**

Node.js и терминал на рабочем ПК не нужны.

## Первый вход

1. Откройте приложение → **Регистрация**
2. Нужны: имя, почта, пароль, подтверждение пароля  
   Пароль по умолчанию скрыт, можно нажать «Показать»
3. Зарегистрироваться можно **только с почтой из белого списка**

Учётная запись с почтой **`kostya.alone18@yandex.ru`** при регистрации автоматически становится **админом** (эта почта уже в whitelist).

### Роли

| Роль | Права |
|---|---|
| Читатель (`user`) | Только просмотр |
| Редактор (`editor`) | Добавление и изменение тем, синхронизация с Диском |
| Админ (`admin`) | Всё выше + настройки пользователей, whitelist, токен Диска |

## Интерфейс

- Слева от выбора отдела — **статус синхронизации** («Актуально», «Есть локальные изменения», «Синхронизация временно занята…» и т.п.)
- Кнопка **«Синхронизировать»** — у редактора/админа, когда есть локальные изменения; после успешной отправки пропадает
- **Добавить** — только у редактора и админа
- Иконка шестерёнки (только админ) — настройки
- Иконка пользователя — имя, почта, выход
- Если на Диске есть более новая версия приложения — синий кружок на иконке профиля и кнопка **«Обновить»** под «Выйти»

## Обновления приложения

Установленное приложение проверяет файл **`app-update.json`** в папке **`REST INFO`** на Яндекс.Диске и сравнивает версию с текущей. Установщик скачивается **только с Диска** из пути в манифесте (обычно `updates/REST-INFO-Setup-*.exe`).

- Кнопка и бейдж появляются **только в установленном .exe**, не в `electron:dev`
- Нужен токен Яндекс.Диска (тот же, что для синхронизации данных)
- По кнопке **«Обновить»** открывается диалог «куда сохранить» установщик; после скачивания можно сразу запустить его
- GitHub для обновлений **не используется** (только репозиторий с кодом)

### Как выпустить новую версию

1. Поднимите `version` в `app/package.json` (например `1.1.6`)
2. Обновите `app/resources/data/app-update.json`:

```json
{
  "version": "1.1.6",
  "remoteSetupPath": "updates/REST-INFO-Setup-1.1.6.exe",
  "notes": "Кратко, что изменилось"
}
```

3. Соберите установщик:

```bash
cd app
npm run dist:ascii
```

4. Залейте на Диск манифест и Setup (нужен токен в `%AppData%\rest-info\REST-INFO\settings.json` — приложение хотя бы раз открыто с токеном):

```bash
cd app
node scripts/upload-update-manifest.js release/REST-INFO-Setup-1.1.6.exe
```

5. У пользователей с версией, где уже есть проверка Диска по `remoteSetupPath`, при запуске появятся бейдж и «Обновить»

Первая установка или переход со старой версии без этой логики — скачайте Setup вручную из `REST INFO/updates/`.
`app-update.json` при обычной синхронизации **не заливается** с клиента (только скриптом релиза).
## Синхронизация (Яндекс.Диск)

- Папка на Диске: **`REST INFO`**
- Админ указывает OAuth-токен в настройках
- После запуска локальные данные сразу доступны; в фоне идёт подтягивание с Диска
- Редактор/админ после правок нажимает **«Синхронизировать»**
- Перед отправкой ставится краткая блокировка (`sync.lock.json`); темы **сливаются по id**, при конфликте одной темы — окно выбора «своя / с Диска»
- Новые фото: `media/{id темы}/images/…` в markdown как `images/…`; старые `media/…` продолжают работать
- На Диск уходят только изменённые media из `pending-media.json` + JSON гайдов

Токен можно получить в кабинете Яндекс OAuth для приложения с доступом к Диску.

## Как вносить изменения в код/данные

### Правки в уже установленном приложении

- Читатель — только смотрит
- Редактор/админ — «Добавить» / «Изменить», затем **«Синхронизировать»**  
  Пересборка установщика **не нужна**

### Правки программы (этот репозиторий)

```bash
cd app
npm install
npm run electron:dev
```

После изменений кода **пересоберите установщик** и выложите на Диск (см. «Обновления»).

| Что изменили | Нужен новый Setup.exe? |
|---|---|
| Код (`app/src`, `app/electron`) | Да |
| Seed JSON / `app-update.json` в `app/resources/data/` | Да (и выкладка на Диск) |
| Темы через UI + синхронизация | Нет |
| README | Нет |

### Сборка установщика

Из‑за кириллицы в пути проекта используйте:

```bash
cd app
npm run dist:ascii
```

Локально: `app/release/REST-INFO-Setup-1.1.4.exe`  
На Диске: `REST INFO/updates/REST-INFO-Setup-1.1.4.exe`

## Структура

```
README.md
app/
  electron/                    ← окно, auth, Яндекс.Диск, обновления
  src/                         ← интерфейс
  resources/data/              ← seed JSON + app-update.json
  scripts/dist-ascii.js        ← сборка Setup при кириллице в пути
  scripts/upload-update-manifest.js  ← выгрузка обновления на Диск
  release/                     ← Setup.exe (не в git)
```

Локальные данные пользователя: `%AppData%\rest-info\REST-INFO\`  
Там же: гайды, `media/`, `pending-media.json`, `.sync-base/`, `app-update.json` (копия с Диска).
